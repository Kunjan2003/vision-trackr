# WorkPulse — Windows Desktop Productivity Tracker

WorkPulse is a **Windows desktop application**, not a website. It consists of an Electron + React + TypeScript dashboard and draggable floating timer, a Python 3.11+ tracking agent, a FastAPI local interface, and SQLite with Alembic migrations. Its code is maintained in this repository.

## Included features

- Private first-run registration (name, email, password, department / role) and login, bcrypt password hashing and 30-day JWT
- Samples Windows foreground application and visible window title every 3–5 seconds; idle detection uses GetLastInputInfo
- Productive / neutral / non-productive categories with configurable matching rules, including site names appearing in browser tab titles
- Work, idle and break time, productive vs non-productive time, daily productivity percentage, multiple daily sessions and finish-day controls
- SQLite storage with UTC timestamps and reporting by the user's local time zone; durable handling of restart / unknown sleep gaps
- Mini always-on-top timer with compact pill mode, break/resume and finish-day confirmation; system tray
- Today / week / month reporting, daily stacked bar chart, trend chart, donut, activity heatmap, app leaderboard and timeline
- CSV and PDF exports, tracking settings and dark/light dashboard themes
- Windows startup integration and PyInstaller + electron-builder NSIS packaging
- Local-only tracking: **no screenshots, keylogging, cloud sync, telemetry, or network-based tracking**

## Development on Windows

Requirements: Windows 10/11, Python 3.11+, Node.js 22+, npm.

Open PowerShell in this repository's root, then run:

    py -3.11 -m venv .venv
    .\.venv\Scripts\Activate.ps1
    python -m pip install -r backend\requirements.txt pillow
    python scripts\make_icons.py
    $env:WORKPULSE_PYTHON = (Resolve-Path ".venv\Scripts\python.exe").Path
    cd desktop
    npm install
    npm run dev

Electron starts and supervises the Python agent. The agent binds **127.0.0.1 on a random local port** and prints the selected port to Electron over stdout. Requests use a random ephemeral application capability header; authenticated routes additionally require a bearer JWT. The React renderer communicates with the local API via the Electron preload/main bridge, so local bearer tokens and agent capabilities are not exposed to the renderer. Live updates flow over FastAPI WebSocket to the Electron main process and onward to the UI.

First run prompts for registration and an explicit tracking/privacy acknowledgement. Successful registration starts tracking immediately. The database is saved in %LOCALAPPDATA%\WorkPulse\workpulse.db. On subsequent launches, WorkPulse can restore its session using Electron safeStorage encryption (or ask you to log in when OS encryption is unavailable). Unfinished tracking sessions resume, while unobserved time since shutdown/sleep is never charged.

### Backend standalone

For diagnostics, from the repository root:

    $env:PYTHONPATH = (Resolve-Path "backend").Path
    $env:WORKPULSE_AGENT_TOKEN = "set-a-fresh-secret-long-and-random"
    python -m workpulse

The local FastAPI docs can be inspected at http://127.0.0.1:PORT/docs, using the startup port. Protected endpoints require the local capability header, and user endpoints also need the signed JWT.

## Tests

From the root (with the venv enabled):

    $env:PYTHONPATH = (Resolve-Path "backend").Path
    python -m pytest -q backend\tests

Then build/check the React UI:

    cd desktop
    npm run build:ui

Tests cover work classification, idle, breaks, crash-gap recovery, midnight splitting, registration, capability restrictions, JWT auth and export endpoints. The GitHub Actions workflow runs backend tests and TypeScript builds, then builds a Windows installer.

## Build the Windows installer

From the root, use:

    .\scripts\build-windows.ps1

The script installs Python build requirements, tests the backend, creates icons, bundles the Python agent into one executable with PyInstaller, and builds a Windows NSIS installer with electron-builder.

**Output:** desktop\release\WorkPulse-Setup.exe

Users who install this .exe do not need Python or Node installed. You can also download the installer from **Actions → WorkPulse CI and Windows Installer → latest successful run → Artifacts → WorkPulse-Windows-Installer**.

The installer is **unsigned**: Windows SmartScreen may warn until the release is code-signed by a trusted publisher. On a Windows PC, verify taskbar/tray, startup registration, foreground app titles, lock/unlock and sleep/resume prior to organizational deployment.

## API

All API calls (except the OpenAPI schema/documentation pages) require the unpredictable X-Agent-Token capability. Authenticated data routes additionally require Authorization: Bearer <JWT>.

| Route | Method | Purpose |
|---|---|---|
| /auth/status | GET | Determine whether a local account exists |
| /auth/register, /auth/login, /auth/me | POST / POST / GET | Account and login |
| /session/start, /break, /resume, /finish | POST | Session controls |
| /activity/live | GET | Current activity and session |
| /ws/live | WebSocket | Live timer updates |
| /stats/day, /stats/week, /stats/month | GET | Analytics (day=YYYY-MM-DD, tz=UTC-minus-local minutes) |
| /categories, /categories/{id} | GET / POST / PUT / DELETE | Application and website patterns |
| /settings | GET / PATCH | Tracking preferences |
| /export?format=csv or pdf | GET | Report for the selected date |

Productivity % = productive seconds / (productive + neutral + non-productive + idle seconds) × 100. Breaks are not counted toward work. Browser classification depends on site names in visible window titles; WorkPulse does not read URLs or browser history.

## Privacy and data ownership

WorkPulse does not record keystrokes or screenshots, upload collected data, or track web requests. It does store foreground executable names and **window titles** (which can contain document or customer names) and the time spent on them. All data is in your local SQLite database. App sign-in tokens are encrypted using the operating system's secure storage when supported; Python JWT signing keys are also held locally.

To erase tracked activity permanently, **quit WorkPulse** and remove %LOCALAPPDATA%\WorkPulse\workpulse.db (and accompanying -wal/-shm files); that also erases the registered local user. Export any reports you need first.

## Verification status

The source is designed for Windows 10/11. Automated checks and the packaged build workflow are included; physical Windows acceptance testing for sleep/wake, app focus behavior, tray, registry startup and installer signing is still required for a production release. The present release supports one local user, not remote workforce administration.
